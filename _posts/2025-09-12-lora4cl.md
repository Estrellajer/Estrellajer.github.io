这系列方法的本质目的是什么？到底把持续学习的困境转换成了什么问题
> 💡 真正的遗忘在于分类器，对齐分类器?（SLCA）


> 持续学习（Continual Learning）的老问题是 catastrophic forgetting——学了新的、忘了旧的。LoRA 这类 PEFT 方法给了一条新路：与其动整个预训练权重，不如只在一个低秩子空间里做更新，把「学习新任务」变成「给老参数开一条不互相打架的小支路」。于是问题从「怎么不忘记」被重新表述成「怎么让新旧任务的更新落在互不干扰的子空间里」。下面 5 篇工作，分别从**干扰消除、近正交参数空间、层级梯度相似树、子空间正则、解析路由**五个角度回答这同一个问题——也是「把 LoRA 玩出花」的五种玩法。

> 这 5 篇可以归到两条主线：**子空间隔离派**（InfLoRA / BiLoRA / CLoRA / AnySSR，都在想办法让更新落在互不干扰的子空间）和 **结构共享派**（TreeLoRA，反过来利用任务相似性共享 LoRA）。它们共同的核心假设是「遗忘来自参数更新的相互干扰」——但如文末会追问的，**真正的遗忘到底在权重里、还是在分类器里**，这本身就是个开放问题。


# 《InfLoRA: Interference-Free Low-Rank Adaptation for Continual Learning》（InfLoRA-CVPR2024）
## MotivationAlthough existing continual learning methods based on PEFT have demonstrated superior performance compared to those not based on PEFT, most of them do not consider how to eliminate the interference of the new task on the old tasks, which inhibits the model from making a good trade-off between stability and plasticity.
## InsightProposition 1 has demonstrated that using our InfLoRA to train the model is equivalent to directly finetuning the pre-trained weight W within the subspace span\{bt1, ..., btr\}. Therefore, before learning the t-th task, we can design matrix Bt such that learning the t-th task in the subspace span\{bt1, ..., btr\} will not interfere with the performance of the model on the old tasks.（没有找到明显的阐述insight的语句，感觉更多的像是发现sequential SVD可以迁移过来）
## Method
> 来一个新任务 → 设计专属子空间 BtB_tBt → 开一条小支路只训练 AtA_tAt。
> 用 local CE 学完后 → 用 DualGPM 保存梯度信息 → 把支路合并回主网络。
> 最后冻结这个支路。
> 结果：不破坏旧任务、参数量保持稳定、能继续学新任务

# 《TreeLoRA: Efficient Continual Learning via Layer-Wise LoRAs  Guided by a Hierarchical Gradient-Similarity Tree》（TreeLoRA-ICML2025）
## MotivationAlthough there exist some continual learning methods developed for LPMs , they often do not focus on the efficiency in CL, typically exhibiting computational complexity that scales linearly with the number of tasks. Consequently, this raises a critical new challenge: How to develop an efficient continual learning approach, particularly fitted for large pre-trained models?
## InsightSome tasks exhibit similar characteristics and can be grouped together, allowing for the use of task-shared knowledge to improve performance and accelerate adaptation to new tasks.Conversely, tasks that differ significantly or even conflict with others are handled separately to alleviate catastrophic forgetting.
## Method
> TreeLoRA structure begins with a root node and incrementally builds a hierarchical tree structure as new tasks arrive. For each incoming task, it utilizes a bandit algorithm to identify the most suitable branch that shares similar gradient directions. Sparse gradient updates are then performed to efficiently adapt the model parameters while retaining previously acquired knowledge. At the end of each task stream, the key parameters of that task are recorded, and the TreeLoRA structure is updated accordingly.

## LimitationTreeLoRA的树是增量构建的 ，这意味着树的最终形态与任务的出现顺序密切相关。一个“糟糕”的任务顺序（例如，先来一系列高度相似的任务，再来一系列完全不相关的任务）可能会导致一个次优的、不平衡的树结构 。这是否会永久性地影响后续所有任务的学习效率和效果？TreeLoRA的核心是“寻找并利用相似性”。如果模型遇到一系列彼此之间毫无关联的任务（例如，代码生成、财务报表分析、古诗词创作），TreeLoRA试图寻找相似性的机制本身是否会成为一种负担，甚至导致“负迁移”（Negative Transfer）现象，即相似的结构反而干扰了学习？

# 串起来看：把 LoRA 玩出花之后，还剩什么
把 5 篇放在一起，能看到一条清晰的演进：**InfLoRA** 用 DualGPM 显式估计「对旧任务无干扰的子空间」，靠的是算；**BiLoRA** 觉得显式消除太贵，改成用 bilinear+DFT 在概率上达到「几乎正交」，靠的是设计；**CLoRA** 则更轻，直接用正交子空间正则把一块区域设为「更新豁免区」；**AnySSR** 把这套正交子空间思路推到解析解（递归最小二乘），干脆不迭代；**TreeLoRA** 走了另一条路——不追求隔离，反而利用任务间的梯度相似性建树共享。
它们都把「持续学习的困境」转换成了同一个更具体的问题：**怎么让新旧任务的参数更新落在互不干扰的子空间里**。这是「把 LoRA 玩出花」的主旋律。


> 但有几个反问值得留在最后：




> 所以「如何把 LoRA 玩出花」——5 篇给出了从显式消除、概率正交、层级共享、正则豁免到解析路由的完整谱系，花是真玩出来了。但花下面那根根——「遗忘到底从何而来、子空间隔离是不是治标」——仍是开放问题。下一阶段，与其继续雕花，不如回头验证这个共同的根假设。
